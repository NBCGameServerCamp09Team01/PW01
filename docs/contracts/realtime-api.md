# 실시간 연결 명세 (Realtime API)

> 버전: v1.5 · 상태: 초안 · 연결: 게임 클라이언트(UE) ⇄ 웹서버(WebSocket) · 게임 담당: Juunnmmoo · 웹서버 담당: Juunnmmoo (리뷰: Sang-Hyun-Kim 배정)

로그인한 게임과 웹서버를 WebSocket 하나로 이어 둡니다(S7). 이 연결이 하는 일은 둘입니다.

1. **세션 유지**: 서버가 보내는 Ping에 게임이 Pong으로 답할 때마다 세션을 다시 10분으로 늘립니다. 10분이 넘는 스테이지 플레이 중에도 로그인이 풀리지 않습니다.
2. **알림**: 서버가 게임에 먼저 알립니다(다른 곳 로그인 등). 알림 줄의 다음 기능(우편함·공지·점검·이용 제한)은 아래 [메시지 종류](#메시지-종류) 표에 줄을 더해 같은 틀을 씁니다.

- 시각·ID·오류 응답 모양: [README.md 공통 규칙](README.md#공통-규칙)
- 인증(토큰, 세션 연장, 401 네 종류): [auth-api.md 인증](auth-api.md#인증)
- Redis 키·스크립트: [redis-keys.md](redis-keys.md) v1.7. 이 명세는 새 키를 만들지 않습니다(접속 상태 키는 길드 기능이 [redis-keys.md 접속 상태](redis-keys.md#접속-상태v16)에 둠). 연결 목록은 서버 메모리에 두고, 서버 사이 전달은 Redis Pub/Sub 채널을 씁니다([서버 여러 대](#서버-여러-대), [redis-keys.md 실시간 서버 사이 전달](redis-keys.md#실시간-서버-사이-전달v15))

## 원칙

| 항목 | 규칙 |
|---|---|
| 알림 전용 | WebSocket은 **알림 채널**입니다. 상태를 바꾸는 요청(로그인, 결과 제출, 투자 등)은 지금처럼 HTTP로 합니다 |
| 놓칠 수 있음 | 연결이 끊긴 동안 생긴 알림은 다시 보내지 않습니다. 알림을 놓쳐도 되도록, 알림이 가리키는 상태는 언제나 HTTP로 다시 받을 수 있어야 합니다 |
| 세션 판정 | HTTP와 같은 규칙입니다. 웹서버 `AuthService.authenticate` → `SessionStore.touch` → 정상 / 세션 없음 / 다른 곳 로그인 |
| 계정당 연결 하나 | 계정당 세션이 하나이므로 연결도 하나입니다. 새 것이 이깁니다 |

## 연결

| 항목 | 값 |
|---|---|
| 경로 | `/realtime` (공통 규칙 "경로는 기능 이름부터") |
| 주소 | `ws://<서버>/realtime` (배포에서 TLS를 쓰면 `wss://`) |
| 인증 | 핸드셰이크 요청 헤더 `Authorization: Bearer <accessToken>`. 쿼리 문자열에 토큰을 싣지 않습니다 |
| Origin | 서버는 `Origin` 헤더를 검사하지 않습니다. UE(libwebsockets)는 접속 주소(예: `localhost`)를 `Origin`으로 보냅니다. 인증은 `Authorization` 헤더로만 하고 쿠키를 쓰지 않으므로 Origin 검사가 필요 없습니다 |
| 언제 연결 | 로그인(A2) 성공 직후 |
| 언제 끊음 | 로그아웃(A5), 세션이 끝났을 때(아래 [종료 코드](#종료-코드)) |
| 연결 수명(UE) | GameInstance 서브시스템이 갖습니다. 레벨(타이틀·메인메뉴 ↔ 스테이지)을 옮겨도 연결은 유지됩니다 |
| 프레임 | 텍스트 프레임(UTF-8 JSON)만 씁니다. 바이너리 프레임은 쓰지 않습니다 |

### 핸드셰이크 결과

핸드셰이크는 HTTP 요청이므로 실패하면 HTTP 상태 코드와 [공통 오류 응답](README.md#오류-응답) 본문으로 답합니다.

| 상태 코드 | 의미 | 게임 쪽 처리 |
|---|---|---|
| 101 | 연결됨. 인증을 통과했으므로 세션도 연장됨 | 메시지를 기다림 |
| 401 | 인증 실패. 코드는 [auth-api.md 인증 확인 순서](auth-api.md#인증-확인-순서와-실패-코드)의 네 가지 | HTTP 401과 같게 처리(다시 연결하지 않음) |
| 503 | Redis에 닿지 못함(`SERVICE_UNAVAILABLE`) | 다시 연결(아래 [다시 연결](#다시-연결)) |

- UE `IWebSocket`은 핸드셰이크가 실패해도 상태 코드를 알려 주지 않습니다(오류 문자열만). 그래서 게임은 연결에 실패하면 **접속 점검(A4)으로 세션 상태를 확인**합니다. A4가 401이면 HTTP 401과 같게 처리하고 다시 연결하지 않습니다. 401이 아니면(연결 실패·503 등) 다시 연결합니다.

### 같은 계정의 연결이 겹칠 때

| 상황 | 서버 처리 |
|---|---|
| 같은 토큰으로 새 연결(게임이 다시 연결함) | 이전 연결을 종료 코드 `4000`으로 닫고 새 연결을 남깁니다 |
| 다른 토큰으로 새 로그인(A2, 다른 곳 로그인) | 로그인을 처리할 때 이전 연결에 `SESSION_REPLACED`를 보내고 종료 코드 `4001`로 닫습니다. 이전 기기가 다음 heartbeat를 기다리지 않고 바로 압니다 |

- 웹서버 근거: 로그인 서비스가 새 세션을 만든 뒤 "이 계정에 새 세션이 생김" 이벤트를 냅니다(S1 코드에 알림 자리 추가, c·d 리뷰). 그 순간 그 계정에 붙어 있는 연결은 이전 세션의 것이므로 실시간 쪽이 `SESSION_REPLACED`를 보내고 닫습니다. 알림에 실패해도 로그인은 성공합니다.
- 이전 연결이 **다른 서버**에 붙어 있어도 로그인 서버가 다른 서버들에 "그 계정의 연결 세션을 다시 확인하라"를 넘기므로 보통 1초 안에 `4001`이 옵니다(아래 [서버 여러 대](#서버-여러-대)). 그 전달을 놓치면 다음 Pong(최대 60초)에서 같은 처리가 됩니다.
- 로그아웃(A5)도 같은 방식으로 그 계정의 연결을 `1000`으로 닫습니다.

## Heartbeat (세션 유지)

WebSocket 표준 Ping/Pong을 씁니다(RFC 6455). 앱 메시지가 아닙니다.

| 항목 | 규칙 |
|---|---|
| Ping | 서버가 연결마다 **60초**마다 보냅니다(설정 `pw01.realtime.ping-interval=60s`) |
| Pong | 게임이 Ping을 받으면 Pong으로 답합니다 |
| 연장 | 서버가 Pong을 받으면 `SessionStore.touch`(= `session_extend.lua`)로 세션을 다시 10분으로 겁니다 |
| 연장 결과 | 정상 → 계속 / 세션 없음 → 종료 코드 `4002`로 닫음 / 다른 곳 로그인 → `SESSION_REPLACED`를 보내고 `4001`로 닫음 |
| Pong이 없을 때 | 연속 **3번**(설정 `pw01.realtime.max-missed-pongs=3`) Ping에 Pong이 없으면 서버가 종료 코드 `4003`으로 닫습니다 |
| 게임 쪽 감시 | 하지 않습니다. UE `IWebSocket`은 Ping을 받았다는 알림을 주지 않습니다. 게임은 연결 종료·오류 이벤트와 서버의 `4003`으로 끊김을 압니다 |

값의 관계(redis-keys.md [값의 관계](redis-keys.md#값의-관계)와 같은 규칙): **세션 수명(10분) > Ping 간격 × 허용 연속 실패(60초 × 3 = 3분).** 세션 수명이나 Ping 간격을 바꿀 때 이 관계를 다시 봅니다.

## 다시 연결

| 항목 | 규칙 |
|---|---|
| 언제 | 종료 코드가 [종료 코드](#종료-코드) 표에서 "다시 연결: 예"일 때, 연결이 비정상으로 끊겼을 때(1006), 핸드셰이크가 503일 때 |
| 간격 | 1 → 2 → 4 → 8 → 16 → 30초, 그 뒤로 30초마다 |
| 횟수 | 로그인해 있는 동안 계속 시도합니다. 세션이 끝났으면 A4가 401이 되므로(위 [핸드셰이크 결과](#핸드셰이크-결과)) 그때 멈춥니다 |
| 로그인 유지 | **연결이 끊긴 것만으로는 로그인을 끝내지 않습니다.** 로그인이 끝나는 것은 서버가 401(만료·다른 곳 로그인·로그아웃)을 주거나 종료 코드 `4001`·`4002`를 받았을 때뿐입니다 |
| 끊긴 동안 세션 | 게임은 실시간 연결이 없는 동안 접속 점검(A4)을 정한 간격으로 보내 세션을 유지하고 401을 알아챕니다([auth-api.md A4](auth-api.md#a4-접속-점검-임시--post-authheartbeat)). 연결 실패가 이어져도 로그인은 끝내지 않습니다 |
| 메뉴 | 다시 연결하는 동안 작은 "재연결 중" 표시를 띄웁니다(화면은 게임이 정함) |
| 플레이 | 스테이지 중에는 플레이를 끊지 않고 뒤에서 다시 연결합니다 |
| 10분 넘게 끊김 | 세션이 끝납니다. 다음 A4(또는 다른 인증 요청)가 401 `AUTH_SESSION_NOT_FOUND` → 로그인 화면. 끊긴 동안의 결과 보관·재전송은 S2·S5가 맡습니다(대계획 Q9) |
| 토큰 | 다시 연결할 때도 같은 토큰을 씁니다(토큰은 로그인할 때만 바뀜) |

## 메시지

### 봉투

서버 → 게임 메시지는 모두 아래 모양입니다.

```json
{
  "type": "SESSION_REPLACED",
  "id": "5b0e7f3a-1c2d-4e5f-8a9b-0c1d2e3f4a5b",
  "sentAt": "2026-10-08T05:00:00.123Z",
  "data": {}
}
```

| 필드 | 타입 | 설명 |
|---|---|---|
| `type` | string | 메시지 종류. 대문자와 `_`. 아래 [메시지 종류](#메시지-종류) 표의 값 |
| `id` | string | 메시지 번호(서버가 만든 UUID). 같은 `id`가 다시 오면 게임은 한 번만 처리합니다. 문의할 때 이 값으로 서버 로그를 찾습니다 |
| `sentAt` | string | 서버가 보낸 시각(UTC, 공통 규칙) |
| `data` | object | 종류별 내용. 내용이 없으면 빈 객체 `{}`(null이 아님) |

- 게임은 **모르는 `type`이면 무시**합니다(서버가 먼저 새 종류를 배포해도 옛 게임이 깨지지 않음).
- 게임은 봉투와 `data`에 모르는 필드가 있으면 무시합니다(공통 규칙 "모르는 필드").
- 게임 → 서버 메시지는 v1에 없습니다. 서버는 게임이 보낸 텍스트 메시지를 읽지 않고 버립니다.

### 메시지 종류

| `type` | 상태 | 언제 보냄 | `data` | 게임 쪽 처리 | 그 뒤 연결 |
|---|---|---|---|---|---|
| `SESSION_REPLACED` | v1 구현 | 같은 계정이 다른 곳에서 로그인함(A2) 또는 Pong으로 연장하다 다른 곳 로그인을 알게 됨 | `{}` | "다른 곳에서 로그인" 안내 후 타이틀(HTTP 401 `AUTH_SESSION_REPLACED`와 같은 처리) | 서버가 `4001`로 닫음 |
| `ACCOUNT_CHANGED` | **예약**(v1에서 서버가 보내지 않음) | 이 게임이 보낸 HTTP 요청이 아닌 경로로 계정 진행이 바뀌었을 때. 보내는 경우가 생기면 이 칸에 적고 v1.1로 올림 | `{ "version": 3 }` (바뀐 뒤의 계정 스냅샷 `version`) | 지금 가진 `version`보다 크면 `GET /accounts/me`(A3)로 스냅샷을 다시 받음 | 유지 |
| `CHAT_MESSAGE` | **초안**(M23 채팅 — 채팅 담당 PR에서 확정) | 전체 채팅 또는 길드 채팅이 보내졌을 때(서버 저장·처리 뒤). 전체는 접속한 모두에게, 길드는 그 길드원에게만 | 채팅 한 줄: `{ "messageId": "1042", "scope": "GUILD", "guildId": "7", "senderAccountId": "12", "senderNickname": "용사", "text": "안녕", "sentAt": "…Z" }`. `scope`는 `GLOBAL`·`GUILD`, 전체면 `guildId`는 `null` | `scope`로 탭(전체·내 길드)을 골라 아래에 붙임. `GUILD`인데 `guildId`가 지금 내 길드가 아니면 버림. 같은 `messageId`는 한 번만 | 유지 |
| `GUILD_MEMBER_JOINED` | **합의**(M23 길드, v1.4) | 길드장이 가입 신청을 수락함([guild-api.md G8](guild-api.md#g8-신청-수락--post-accountsmeguildjoin-requestsjoinrequestidapprove)). 받는 사람: 길드원 전부(새 사람 포함) | `{ "guildId": "7", "accountId": "57", "nickname": "궁수", "memberCount": 4 }` | 아래 [길드 알림 처리](#길드-알림-처리). 새 사람이 나 자신이면 G4로 소속이 생겨 길드 팝업(열려 있으면)이 길드원 화면으로 바뀜 | 유지 |
| `GUILD_MEMBER_LEFT` | **합의**(M23 길드, v1.4) | 길드원이 탈퇴(G11)하거나 내보내짐(G10, Lv2). 받는 사람: 남은 길드원 + 나간 사람 | `{ "guildId": "7", "accountId": "57", "memberCount": 3, "reason": "LEFT" }`. `reason`은 `LEFT`(탈퇴) · `KICKED`(내보내기, Lv2부터) | 길드 알림 처리. 나간 사람이 나 자신이면 G4로 미소속 화면이 됨. `KICKED` 안내 문구("길드에서 내보내졌습니다")는 내보내기(Lv2 보류)와 함께 | 유지 |
| `GUILD_DISBANDED` | **합의**(M23 길드, v1.4) | 길드장이 해체함(G12, 혼자인 길드장의 탈퇴 포함). 받는 사람: 해체 직전 길드원 + 그 길드에 신청 중이던 사람 | `{ "guildId": "7" }` | 길드 알림 처리. 길드원은 G4로 미소속 화면이 되고, 신청자는 내 신청 목록에서 빠짐. 따로 띄우는 안내 문구는 없음(아래 길드 알림 처리) | 유지 |
| `GUILD_JOIN_REQUESTED` | **합의**(M23 길드, v1.4) | 누가 가입을 신청함(G5). 받는 사람: 그 길드의 길드장 | `{ "guildId": "7", "joinRequestId": "105", "accountId": "88", "nickname": "초보", "pendingCount": 2 }`. `pendingCount`는 대기 중 신청 수 | 길드 알림 처리(길드장 표시·받은 신청 수) | 유지 |
| `GUILD_JOIN_REJECTED` | **합의**(M23 길드, v1.4) | 길드장이 내 신청을 거절함(G9). 받는 사람: 신청자 | `{ "guildId": "7", "guildName": "새벽기사단", "joinRequestId": "105" }` | 길드 알림 처리. G4로 내 신청 목록에서 빠짐. `guildName`은 안내 문구("○○ 길드가 신청을 거절했습니다")를 띄울 때 쓰는 값(지금 게임은 띄우지 않음) | 유지 |
| `PRESENCE_CHANGED` | **합의**(M23 길드 Lv2, v1.5) | 길드원의 접속 상태가 **실제로 바뀌었을 때**: 접속하지 않은 상태에서 연결됨 → `true`, 마지막 연결이 끊김 → `false`. 다시 붙음·다른 서버로 옮김은 보내지 않음(아래 [접속 표시 처리](#접속-표시-처리)). 받는 사람: **본인을 뺀** 그 길드원. 미소속·혼자인 길드는 보내지 않음 | `{ "guildId": "7", "accountId": "57", "online": true }` | 길드원 목록에서 그 사람의 접속 표시를 **값으로 바로** 고침(G4를 다시 받지 않음). 목록에 없는 사람이면 G4 다시 받기 | 유지 |

- `ACCOUNT_CHANGED`는 틀을 정해 두려고 표에 둡니다. 계정당 접속이 하나이고 계정 값은 이 게임이 HTTP로 바꾸므로(그 응답으로 새 값을 받음), 지금은 보낼 경우가 없습니다. 게임은 받았을 때의 처리를 v1에서 만들지 않아도 됩니다(받으면 무시해도 규칙 위반이 아님).
- **초안** 줄은 이름과 `data` 틀만 먼저 정해 둔 것입니다(두 담당이 같은 표를 따로 고치지 않게). 각 담당이 자기 줄을 확정하는 PR을 냅니다. 서버가 아직 보내지 않는 동안 게임이 받으면 무시해도 됩니다.
- `messageId`는 게임이 모양(숫자·UUID)에 기대지 않는 문자열입니다. 같은지 비교하거나 받은 값을 그대로 돌려 보내는 데만 씁니다. 지금 전체 채팅은 서버에 저장하지 않아 UUID이고, 길드 채팅은 저장 번호입니다. 전체 채팅을 저장하게 되면 모양이 바뀔 수 있습니다.
- 길드에 관한 메시지(`CHAT_MESSAGE`의 길드 채팅, `GUILD_*`, `PRESENCE_CHANGED`)는 **그 길드원에게만** 갑니다(위 표의 "받는 사람"처럼 나간 사람·신청자가 더해질 수 있음). 한 사람은 길드 하나에만 들 수 있습니다.

#### 길드 알림 처리

- 서버는 길드 데이터가 **커밋된 뒤에** `GUILD_*`를 보냅니다. 되돌려진 요청의 알림은 나가지 않습니다.
- 게임은 `GUILD_*`를 **신호로만** 씁니다. 받으면 0.5초 동안 더 오는 길드 알림을 모아, [guild-api.md G4](guild-api.md#g4-내-길드--get-accountsmeguild) `GET /accounts/me/guild`를 **한 번** 다시 받아 길드 화면을 그립니다. `data`의 `memberCount` 등은 다시 받기 전 잠깐 보이는 값입니다.
- 이유: 알림은 놓칠 수 있고([원칙](#원칙)) 다른 서버에서 온 알림끼리 순서가 바뀔 수 있습니다. 다시 받은 G4가 늘 맞는 값입니다.
- 길드 화면이 닫혀 있어도 내 소속이 바뀌는 알림(내가 들어감·나감·해체)은 처리해 메인메뉴 길드 표시와 채팅 길드 탭을 맞춥니다.
- 지금 게임은 길드 알림을 받아도 따로 안내 문구(토스트·팝업)를 띄우지 않고 화면만 바꿉니다(메인메뉴 [길드] 배지 = 받은 신청 수). 안내 문구는 후속입니다.
- `PRESENCE_CHANGED`는 이 규칙의 예외입니다. 아래 [접속 표시 처리](#접속-표시-처리).

#### 접속 표시 처리

서버는 [redis-keys.md 접속 상태](redis-keys.md#접속-상태v16) 키가 **바뀔 때만** 보냅니다.

| 일 | 접속 상태 키 | 보냄 |
|---|---|---|
| 처음 연결(키가 없었음) | `SET … GET`의 전 값이 없음 | `online: true` |
| 같은 서버·다른 서버로 다시 붙음 | 전 값이 있음(서버 번호만 바뀜) | 없음 |
| Pong(60초마다) | 보통 전 값이 있음. 키가 수명이 다해 사라졌다가 다시 생기면 전 값이 없음 | 없음 / `online: true` |
| 끊김, 키 값이 이 서버 | `presence_release.lua`가 지움(1) | `online: false` |
| 끊김, 이미 다른 서버로 옮김 | 값이 달라 지우지 않음(0) | 없음 |

- 게임은 `data` 값으로 그 길드원의 접속 표시를 바로 고칩니다. G4를 다시 받지 않는 이유: 값이 메시지에 다 들어 있고, 30명 길드에서 접속이 바뀔 때마다 G4를 받으면 요청이 몰립니다.
- `guildId`가 지금 내 길드가 아니거나 G4를 아직 받지 않았으면 버립니다(길드를 옮긴 직후의 늦은 알림). 그 사람이 목록에 없으면 목록이 옛것이므로 0.5초 모아 G4를 다시 받습니다.
- 칸이 하나라도 없거나 `online`이 JSON `true`·`false`가 아니면 버립니다(없는 값을 끊김으로 읽지 않음).
- 알려진 한계: 서버가 갑자기 꺼지면 끊김 처리가 없어 `online: false`가 가지 않습니다(키는 150초 뒤 사라지고 다음 G4에서 맞춰짐). 같은 서버에서 끊긴 직후 새로 붙으면 드물게 `false` 뒤 다음 Pong(최대 60초)에서 `true`가 다시 옵니다.
- 접속 표시는 덤입니다. Redis·보내기가 실패해도 연결은 막지 않고 경고 로그만 남깁니다.

#### 이름 규칙

| 규칙 | 예 |
|---|---|
| 대문자와 `_`, `<영역>_<무엇 또는 일어난 일>` | `CHAT_MESSAGE`, `GUILD_MEMBER_JOINED` |
| 영역: `SESSION`(세션·연결) · `ACCOUNT`(계정 진행) · `CHAT`(채팅) · `GUILD`(길드) · `PRESENCE`(접속 상태). 새 영역은 이 명세 리뷰에서 정함 | |
| 일어난 일은 과거형(`JOINED`·`LEFT`·`CHANGED`·`REPLACED`), 물건 자체를 보내면 이름만(`MESSAGE`) | |
| `data` 칸 이름은 camelCase, ID는 문자열, 시각은 UTC(공통 규칙) | `"guildId": "7"` |

- 새 종류를 더할 때: 이 표에 한 줄과 `data` 모양을 먼저 적고(명세 v1.x), 서버 → 게임 순으로 배포합니다. 예정: 우편 도착, 공지·점검, 이용 제한.

예시: `examples/realtime-message-session-replaced.json`, `examples/realtime-message-account-changed.json`, `examples/realtime-message-chat-message.json`, `examples/realtime-message-guild-member-joined.json`, `examples/realtime-message-guild-member-left.json`, `examples/realtime-message-guild-disbanded.json`, `examples/realtime-message-guild-join-requested.json`, `examples/realtime-message-guild-join-rejected.json`, `examples/realtime-message-presence-changed.json`

## 종료 코드

서버가 연결을 닫을 때 WebSocket 종료 코드와 이유 문자열(`WS_` 코드)을 보냅니다.

| 종료 코드 | 이유(`reason`) | 상황 | 게임 쪽 처리 | 다시 연결 |
|---|---|---|---|---|
| 1000 | (없음) | 로그아웃(A5)으로 서버가 닫음 / 게임이 로그아웃하며 닫음 | 없음 | 아니오 |
| 1001 | (없음) | 서버가 내려감(배포·재시작) | 뒤에서 다시 연결 | 예 |
| 4000 | `WS_CONNECTION_REPLACED` | 같은 세션의 새 연결이 생김(보통 게임 자신의 재연결) | 없음. 이 연결만 버림 | 아니오 |
| 4001 | `WS_SESSION_REPLACED` | 다른 곳 로그인. 바로 앞에 `SESSION_REPLACED` 메시지를 보냄 | 안내 후 타이틀(메시지를 못 받았어도 이 코드로 같은 처리) | 아니오 |
| 4002 | `WS_SESSION_ENDED` | 세션이 없음(만료·로그아웃·제재로 끊김). HTTP `AUTH_SESSION_NOT_FOUND`와 같음 | 로그인 화면 | 아니오 |
| 4003 | `WS_HEARTBEAT_TIMEOUT` | 연속으로 Pong이 없음 | 뒤에서 다시 연결 | 예 |
| 그 밖(1006 등) | — | 네트워크 끊김 등 비정상 종료 | 뒤에서 다시 연결 | 예 |

- 4000~4999는 WebSocket 표준에서 앱이 쓰도록 비워 둔 범위입니다.
- 게임은 이유 문자열이 아니라 **종료 코드 숫자**로 판단합니다. 이유 문자열은 로그용입니다.

## 서버 여러 대

연결 목록(계정 → 연결)은 각 서버의 메모리에 있습니다. 서버가 여러 대(로드 밸런서 뒤)여도 알림이 받는 사람에게 가도록, 서버들은 **Redis Pub/Sub으로 메시지를 서로 넘깁니다**(v1.3).

- 알림을 보내는 서버는 자기에게 붙은 연결에는 바로 보내고, 같은 메시지를 Redis 채널에 올립니다. 모든 서버가 채널을 듣다가 **자기에게 붙은 사람에게만** 보냅니다. 채널·모양은 [redis-keys.md 실시간 서버 사이 전달](redis-keys.md#실시간-서버-사이-전달v15).
- 게임에서 보면 달라지는 것이 없습니다. 같은 메시지는 어느 서버에서 오든 `id`가 같습니다.
- **놓칠 수 있음**([원칙](#원칙))은 그대로입니다. Redis가 잠깐 끊긴 동안 넘긴 메시지는 사라집니다.
- **다른 서버에서 보낸 메시지끼리는 순서가 바뀔 수 있습니다.** 순서가 중요한 화면(채팅)은 메시지 안의 번호·시각으로 정렬합니다.
- 다른 곳 로그인: 이전 연결이 다른 서버에 있어도 보통 1초 안에 `SESSION_REPLACED` + `4001`. 서버 사이 전달을 놓치면 그 연결의 다음 Pong 연장에서 "다른 곳 로그인"을 알게 되어 **최대 60초**(Ping 간격) 늦게 같은 처리가 됩니다.
- 로그아웃(A5)은 서버 사이로 넘기지 않습니다. 다른 서버에 남은 연결은 게임이 로그아웃하며 스스로 닫습니다.
- 연결이 끊겨 게임이 [다시 연결](#다시-연결)하면 로드 밸런서가 **살아 있는 서버**로 보냅니다. 서버 한 대가 꺼져도 게임 코드는 바뀌지 않습니다.
- 로드 밸런서의 유휴 시간 제한(배포 설정 120초, 로컬 로드 밸런서도 120초)은 Ping 간격(60초)보다 길어야 합니다. 짧으면 조용한 연결이 끊깁니다.
- 접속 상태(누가 접속해 있나)는 연결한 서버가 Redis에 적습니다([redis-keys.md 접속 상태](redis-keys.md#접속-상태v16)). 어느 서버에 붙었든 같은 값을 읽습니다.

## 설정 값

| 값 | 기본값 | 설정 이름 | 쪽 |
|---|---|---|---|
| Ping 간격 | 60초 | `pw01.realtime.ping-interval=60s` | 웹서버 |
| 허용 연속 Pong 없음 | 3번 | `pw01.realtime.max-missed-pongs=3` | 웹서버 |

| Ping 없음 감시 | Ping 간격 × 3 | (UE `DefaultGame.ini`) | 게임 |
